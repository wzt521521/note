# 宏与头文件保护

> 宏在**预处理阶段**处理，常用于定义标记、替换代码中的符号，以及控制哪些代码参与编译。

## 1. 宏的常见用法

| 用法 | 示例 | 含义 |
| --- | --- | --- |
| 标记宏 | `#define PLAYER_H` | 定义一个不带替换内容的宏，常用于头文件保护 |
| 对象式宏 | `#define MAX_NUM 100` | 将后续代码中的 `MAX_NUM` 替换为 `100` |
| 函数式宏 | `#define SQUARE(x) ((x) * (x))` | 接收参数并进行替换，不是真正的函数 |

```cpp
#define MAX_NUM 100

int scores[MAX_NUM];  // 预处理后相当于 int scores[100];
```

**注意：**正确拼写是 `#define`。定义常量宏时，末尾通常不加分号，否则分号也会成为替换内容。

## 2. `#ifndef`、`#define` 与 `#endif`

这三个指令经常配合使用，用于防止头文件内容重复展开。

| 指令 | 作用 |
| --- | --- |
| `#ifndef PLAYER_H` | 如果尚未定义 `PLAYER_H`，处理下面的代码 |
| `#define PLAYER_H` | 定义 `PLAYER_H`，作为已经处理过该头文件的标记 |
| `#endif` | 结束这一段条件编译 |

### 头文件示例：`player.h`

```cpp
#ifndef PLAYER_H
#define PLAYER_H

void show_player();

#endif  // PLAYER_H
```

### 执行过程

1. **第一次包含：**`PLAYER_H` 尚未定义，进入条件块。
2. 执行 `#define PLAYER_H`，并处理后面的声明等内容。
3. **再次包含：**发现 `PLAYER_H` 已定义，跳过条件块。

```text
第一次 #include "player.h" → 定义标记 → 展开头文件内容
再次   #include "player.h" → 标记已存在 → 跳过头文件内容
```

> **核心补充：作用范围是同一个翻译单元。**一个 `.cpp` 文件及其包含的头文件经预处理后形成一个翻译单元。不同 `.cpp` 文件分别编译时，仍然可以各自包含这个头文件；头文件保护不是“整个项目只包含一次”。

头文件保护宏应尽量唯一，例如 `GAME_PLAYER_H`，避免不同头文件误用同一个宏名。该机制也不能解决多个 `.cpp` 包含同一头文件后，普通非 `inline` 函数定义或全局变量定义造成的链接重复定义问题；此类定义通常应放在 `.cpp` 文件中。[参考：GCC 头文件保护](https://gcc.gnu.org/onlinedocs/cpp/Once-Only-Headers.html)

## 3. 核心补充：条件编译与宏的注意事项

### 3.1 常见条件编译指令

```cpp
#define DEBUG_MODE

#ifdef DEBUG_MODE
// 已定义 DEBUG_MODE 时，保留这里的代码。
#else
// 未定义 DEBUG_MODE 时，保留这里的代码。
#endif
```

- `#ifdef NAME`：判断宏是否已定义。
- `#ifndef NAME`：判断宏是否未定义。
- `#if` / `#elif`：根据预处理常量表达式选择分支。
- `#undef NAME`：取消一个宏定义。

**已定义不等于值为真：**即使写了 `#define DEBUG_MODE 0`，`#ifdef DEBUG_MODE` 仍成立；要根据数值控制开关，应使用 `#if DEBUG_MODE`。

### 3.2 函数式宏的两个常见坑

```cpp
#define SQUARE(x) ((x) * (x))

int value = SQUARE(1 + 2);  // 展开为 ((1 + 2) * (1 + 2))，结果为 9。
```

1. **运算优先级：**参数和整个表达式都应加括号，避免展开后改变计算顺序。
2. **重复求值：**不要写 `SQUARE(i++)` 这类带副作用的调用，参数会被展开多次；在这个例子中还会导致未定义行为。

宏没有普通变量和函数那样的类型检查与作用域规则。C++ 中，常量通常可用 `constexpr`，简单计算通常可用函数替代：

```cpp
constexpr int MAX_NUM = 100;
constexpr int square(int x) { return x * x; }
```

上面的替代示例应独立使用，不要与同名的 `MAX_NUM` 宏放在一起。[参考：GCC 预处理器手册](https://gcc.gnu.org/onlinedocs/cpp/)

---

**记忆重点：**宏先于编译处理；头文件保护防止同一翻译单元内重复展开；函数式宏本质是替换，要注意括号和重复求值。

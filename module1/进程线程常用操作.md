命令	作用	我们用它观察什么
ps aux | grep game_app	从所有进程中查找程序	找进程、PID
pgrep -a game_app	按名字直接查进程	更方便地找 PID
ps -p <PID>	查看指定进程	确认进程是否存在
ps -p <PID> -o pid,ppid,%cpu,%mem,vsz,rss,stat,cmd	自定义显示进程信息	PID、CPU、内存、状态
top -p <PID>	实时监控指定进程	CPU、内存、运行状态
htop	交互式进程监控	更直观地查看整个系统进程
pidstat -p <PID> 1	每秒统计一次指定进程	CPU 使用情况
pidstat -r -p <PID> 1	每秒统计一次内存	VSZ、RSS、%MEM
ps -T -p <PID>	展开指定进程的线程	线程 ID
top -H -p <PID>	实时展开线程	各线程 CPU 使用率


其中我建议你重点形成这几个使用习惯：想找 PID，先用 pgrep -a game_app；想快速看进程，使用 ps -p <PID>；想实时看，使用 top -p <PID> 或 htop；想做性能采样，使用 pidstat -p <PID> 1；想看线程，使用 ps -T -p <PID>。
另外记住几个常用操作：Ctrl+C 终止当前前台程序或停止 pidstat；q 退出 top；F3 在 htop 中搜索；F10 或 q 退出 htop。

top 和 htop 本质上都是看进程、CPU、内存等系统状态的工具，但定位不同：top 更基础、更通用，htop 更友好、更适合交互查看。
top 的优点是几乎所有 Linux 系统默认都有，适合服务器、最小化环境、远程机器上快速排查；缺点是界面偏传统，搜索、排序、选择进程这些操作没那么直观。比如你刚才用了：
top -p 1670
就能只盯着一个 PID 看。
htop 可以理解成“增强版 top”。它通常需要额外安装，但界面更直观，有 CPU 条形图、内存条、彩色显示，也更容易搜索、排序、切换树形视图。你刚才按 F3 搜索 game_app，这就是 htop 很方便的地方。
简单记忆：top = 标配、轻量、哪里都能用；htop = 更好看、更好操作、更适合人工观察。
如果是在面试或实际工作里，我建议你这样用：服务器上先会 top，因为它最可靠；环境允许时用 htop 提高效率。

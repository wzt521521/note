# 网络字节序与大小端 核心笔记

## 一、字节序（Endianness）基本概念
- 定义：多字节数据类型（short/int/long等）在计算机内存中的**字节排列顺序**
- 前提：仅针对≥2字节的数据类型，单字节数据不存在字节序问题
- 本质：CPU硬件读写多字节整数时，对内存地址和字节权重的映射规则

## 二、大端（Big-Endian）与小端（Little-Endian）
以32位整数 `0x12345678` 为例，内存地址从低到高为 `addr[0] → addr[3]`
字节权重从高到低：`0x12（MSB最高有效字节） > 0x34 > 0x56 > 0x78（LSB最低有效字节）`

### 1. 大端模式
- 规则：**高位字节存低地址，低位字节存高地址**
- 内存布局：
  - addr[0] = 0x12
  - addr[1] = 0x34
  - addr[2] = 0x56
  - addr[3] = 0x78
- 特点：和人类书写数字的顺序（左高右低）完全一致

### 2. 小端模式
- 规则：**低位字节存低地址，高位字节存高地址**
- 内存布局：
  - addr[0] = 0x78
  - addr[1] = 0x56
  - addr[2] = 0x34
  - addr[3] = 0x12
- 特点：和人类书写顺序相反；是x86/x86_64架构CPU的默认模式；ARM、RISC-V默认多为小端，可配置

## 三、网络字节序
- 规定：TCP/IP协议栈强制要求，**网络传输链路上的多字节整数必须使用大端字节序**
- 目的：统一传输标准，屏蔽不同CPU架构的字节序差异，保证跨主机通信数据解析正确
- 注意：仅约束「网络传输过程中的字节流」，不修改主机内存的原生存储方式

## 四、htonl / ntohl 系列转换函数
C语言标准库提供，用于主机字节序与网络字节序的边界转换

### 1. 命名拆解
- `h` = host：主机字节序（当前CPU架构的原生字节序）
- `n` = network：网络字节序（大端）
- `to` = 转换
- `s` = short：16位短整型
- `l` = long：32位长整型

### 2. 四个核心函数
| 函数 | 功能 | 典型用途 |
|------|------|----------|
| `htons()` | 主机字节序 → 网络字节序，16位 | 端口号转换 |
| `htonl()` | 主机字节序 → 网络字节序，32位 | IP地址、32位整数发送 |
| `ntohs()` | 网络字节序 → 主机字节序，16位 | 接收端口号解析 |
| `ntohl()` | 网络字节序 → 主机字节序，32位 | 接收IP地址、32位整数解析 |

### 3. 工作原理（x86小端环境为例）
输入：主机序整数 `0x12345678`，内存物理字节为 `[0x78, 0x56, 0x34, 0x12]`
调用 `htonl()` 后：
- 返回一个新的整数，其**内存物理字节排列**变为 `[0x12, 0x34, 0x56, 0x78]`
- 若将返回值当作整数读取，x86会按小端解释为数值 `0x78563412`
- 若将返回值当作字节流直接发送，物理顺序正好是标准网络大端序

> 核心逻辑：利用主机自身的字节序存储规则，反向构造出一个整数，让它在内存中的物理字节布局刚好匹配网络序要求。

## 五、关键误区澄清
1. ❌ 错误：TCP/IP会修改主机内存的存储方式为大端
   ✅ 正确：TCP/IP仅统一传输链路上的字节序，主机内存始终保持CPU原生字节序，转换只在收发边界临时发生

2. ❌ 错误：htonl把整数在内存里改成大端，就和小端CPU冲突了
   ✅ 正确：字节序是「读写解释规则」，不是「内存属性」。同一段内存，当作整数读时按CPU字节序解释，当作字节流发送时按物理地址顺序发送，二者不冲突

3. ❌ 错误：所有数据都需要转网络字节序
   ✅ 正确：只有多字节整数需要；单字节数据、字符串（按字节流处理）不需要转换

## 六、完整收发流程（x86小端主机）
### 发送端
1. 内存中存在主机序整数：`uint32_t num = 0x12345678;` → 内存字节 `[78,56,34,12]`
2. 调用 `htonl(num)` 得到转换值，内存字节变为 `[12,34,56,78]`
3. `send()` 按地址从低到高发送字节 → 网络上传输大端字节流 `12 34 56 78`

### 接收端
1. 从网络收到大端字节流 `12 34 56 78`，存入接收缓冲区
2. 调用 `ntohl()` 将网络序转换为主机序，x86下内存字节变为 `[78,56,34,12]`
3. 当作整数读取，得到正确数值 `0x12345678`

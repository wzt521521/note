下面用一张员工表演示**建表 → 无索引查询 → 建索引 → 用索引查询 → 删索引**的完整过程，对应「书 + 目录」的类比。

### 准备工作：先建一张测试表并插入数据
这一步相当于「印好一本书的正文」。
```sql
-- 建员工表（id 是主键，默认自带主键索引，相当于书的页码目录）
CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(50),
    department_id INT,
    salary INT
);

-- 插入5条测试数据
INSERT INTO employees (id, name, department_id, salary) VALUES
(1, '张三', 1, 10000),
(2, '李四', 1, 8000),
(3, '王五', 2, 9000),
(4, '赵六', 2, 12000),
(5, '孙七', 3, 7000);
```

此时表里的数据：

| id | name | department_id | salary |
|----|------|---------------|--------|
| 1  | 张三 | 1             | 10000  |
| 2  | 李四 | 1             | 8000   |
| 3  | 王五 | 2             | 9000   |
| 4  | 赵六 | 2             | 12000  |
| 5  | 孙七 | 3             | 7000   |

---

### 场景1：没有额外索引时，查询 = 从头翻书
现在要查「部门2的所有员工」：
```sql
SELECT * FROM employees WHERE department_id = 2;
```

**执行过程**：
数据库会从第1行到第5行**逐行检查**，判断 `department_id` 是不是2，最后挑出第3、4行。
这就叫**全表扫描**，相当于翻书从头翻到尾找内容，数据越多越慢。

---

### 场景2：给 department_id 列建索引 = 加一份部门目录
```sql
ALTER TABLE employees 
ADD INDEX idx_dept (department_id);
```

执行完这句话，数据库就会在 `employees` 表上，给 `department_id` 列生成一个名叫 `idx_dept` 的索引。
你可以理解成多了一张「部门目录表」：

| department_id | 对应行位置 |
|---------------|------------|
| 1             | 第1、2行   |
| 2             | 第3、4行   |
| 3             | 第5行      |

> 索引是依附于表存在的附属结构，不会改变表里的原始数据，只是多了一份“快速查找目录”。

---

### 场景3：有索引后再查询 = 先查目录，直接定位
再执行同样的查询：
```sql
SELECT * FROM employees WHERE department_id = 2;
```

**执行过程**：
1.  先去 `idx_dept` 索引里找，查到部门2对应第3、4行；
2.  直接去表里取出这两行数据，不用扫完整张表。

数据量越大，索引的提速效果越明显。

---

### 场景4：删除索引 = 撕掉这份目录
```sql
ALTER TABLE employees 
DROP INDEX idx_dept;
```

执行完，`idx_dept` 这个索引就被删掉了，“部门目录”没了。
再查部门2的员工，又会变回从头扫全表的方式。

---

### 一句话对应关系
- 表 = 正文，存真实数据
- 索引 = 目录，挂在表上，用来加速查询
- 加/删索引 = 修改书的目录结构，所以用 `ALTER TABLE`

### MySQL事务核心介绍

事务是一组**原子性的SQL操作集合**，这组操作要么全部执行成功并永久生效，要么全部失败回滚到初始状态，不会出现部分执行的中间结果。MySQL中只有**InnoDB存储引擎**支持事务，MyISAM等引擎不具备事务能力。

---

### 一、事务四大核心特性（ACID）

这是事务的核心标准，也是数据库事务的基础定义：

1. **原子性（Atomicity）**
事务是不可拆分的最小执行单元。事务内的所有操作，要么全部提交成功，要么全部回滚撤销，不会停留在半执行状态。底层通过`undo log`（回滚日志）实现，日志记录操作的反向逻辑，出错时可回滚到事务开始前的状态。
2. **一致性（Consistency）**
事务执行前后，数据库的完整性约束（如主键唯一、外键约束、业务规则）不会被破坏，数据始终保持合法状态。比如转账场景中，事务执行前后两个账户的总金额保持不变。
一致性是事务的最终目标，原子性、隔离性、持久性都是为了保障数据一致性。
3. **隔离性（Isolation）**
多个并发事务之间相互隔离，互不干扰。数据库通过不同的隔离级别，在数据安全性和并发性能之间做权衡。底层通过锁机制和MVCC（多版本并发控制）实现。
4. **持久性（Durability）**
事务一旦提交成功，对数据的修改就是永久的，即使数据库宕机、崩溃，修改的数据也不会丢失。底层通过`redo log`（重做日志）实现，采用预写日志机制，修改数据前先写日志，宕机后可通过日志恢复数据。

---

### 二、并发事务的三类问题

多个事务同时操作同一份数据时，若隔离控制不足，会出现以下数据异常：

1. **脏读**：一个事务读取到了另一个事务**未提交**的修改数据。如果对方事务回滚，读取到的就是无效的脏数据。
2. **不可重复读**：同一个事务内，多次读取同一条数据，结果不一致。原因是读取间隙中，其他事务修改并提交了这条数据，针对的是数据的`update/delete`操作。
3. **幻读**：同一个事务内，多次执行相同的范围查询，返回的记录行数不一致。原因是读取间隙中，其他事务在该范围内新增/删除了记录，针对的是数据的`insert/delete`操作。

### 三、MySQL的四种隔离级别

SQL标准定义了4种隔离级别，级别越高数据越安全，但并发性能越低。

| 隔离级别 | 解决的异常问题 | 说明 |
| --- | --- | --- |
| 读未提交（READ UNCOMMITTED） | 无 | 可读取其他事务未提交的数据，存在脏读、不可重复读、幻读，生产环境基本不用 |
| 读已提交（READ COMMITTED） | 脏读 | 只能读取其他事务已提交的数据，避免脏读，仍存在不可重复读、幻读   Oracle、SQL Server的默认隔离级别 |
| 可重复读（REPEATABLE READ） | 脏读、不可重复读 | 同一个事务内多次读取同一条数据结果一致，是**MySQL InnoDB的默认隔离级别**   InnoDB通过MVCC+间隙锁，在此级别额外解决了幻读问题 |
| 串行化（SERIALIZABLE） | 脏读、不可重复读、幻读 | 所有事务串行排队执行，完全隔离，但并发性能极差，生产环境几乎不用 |

注意：标准SQL规范中，可重复读级别无法解决幻读；但InnoDB引擎通过Next-Key Lock（行锁+间隙锁）和MVCC机制，在该级别下抑制了幻读。

### 四、事务基础使用

1. 手动控制事务

```
-- 开启事务
BEGIN;
-- 或 START TRANSACTION;

-- 执行业务SQL
UPDATE account SET money = money - 100 WHERE id = 1;
UPDATE account SET money = money + 100 WHERE id = 2;

-- 提交：所有修改永久生效
COMMIT;

-- 回滚：出错时撤销所有修改
ROLLBACK;
```

2. 自动提交机制
MySQL默认开启自动提交（`autocommit=1`），每一条单独的SQL语句都会自动作为一个事务提交。可通过命令关闭：

```
SET autocommit = 0; -- 关闭后，所有SQL都需要手动COMMIT才会永久生效
```

## C++ struct 内存对齐规则与常见情况

内存对齐是编译器为优化内存访问效率、兼容硬件约束，对结构体成员的地址偏移和整体大小进行的地址边界调整。以下是核心规则、典型示例与控制方式。

### 一、核心对齐规则
首先明确三个对齐值概念：
1. **自身对齐值**：基本数据类型本身的大小（如`char=1`、`short=2`、`int=4`、`long long/double=8`、64位指针=8）。
2. **指定对齐值**：编译器预设的对齐边界（MSVC、GCC、Clang默认均为8字节，可通过编译指令修改）。
3. **有效对齐值**：对单个成员，`有效对齐 = min(自身对齐值, 指定对齐值)`；对整个结构体，`有效对齐 = min(成员中最大自身对齐值, 指定对齐值)`。

三条铁则：
1. 结构体**第一个成员的偏移量永远为0**。
2. 后续每个成员的起始偏移量，必须是该成员**有效对齐值的整数倍**，不足则在前一个成员后填充字节。
3. 结构体的**总大小**，必须是结构体整体有效对齐值的整数倍，不足则在结构体末尾填充字节。

### 二、典型计算示例
以下均基于64位环境、默认8字节指定对齐。

#### 1. 基础结构体：成员顺序决定大小
成员顺序不同，填充字节数不同，整体大小差异明显。
```cpp
// 版本1：乱序成员
struct A {
    char a;     // 偏移0，占1字节
    int b;      // 有效对齐4，偏移1不是4的倍数 → 填充3字节，偏移4开始，占4字节（4-7）
    short c;    // 有效对齐2，偏移8是2的倍数，占2字节（8-9）
};
// 整体有效对齐 = max(1,4,2) = 4
// 当前总长度10，不是4的倍数 → 末尾填充2字节
// 最终 sizeof(A) = 12
```

```cpp
// 版本2：从小到大排序成员（最优）
struct B {
    char a;     // 偏移0，1字节
    short c;    // 有效对齐2，偏移1→填充1，偏移2开始，占2字节（2-3）
    int b;      // 有效对齐4，偏移4刚好，占4字节（4-7）
};
// 整体有效对齐=4，总长度8刚好是4的倍数
// 最终 sizeof(B) = 8
```

#### 2. 结构体嵌套
嵌套结构体的有效对齐值，取其内部最大成员的对齐值。
```cpp
struct Inner {
    char c;     // 0
    int i;      // 4-7
};
// sizeof(Inner) = 8，有效对齐=4

struct Outer {
    char a;         // 0
    Inner inner;    // inner有效对齐4，偏移1→填充3，偏移4开始，占8字节（4-11）
    short b;        // 有效对齐2，偏移12刚好，占2字节（12-13）
};
// 整体有效对齐 = max(1,4,2) = 4
// 总长度14 → 末尾填充2字节
// 最终 sizeof(Outer) = 16
```

#### 3. 大类型成员对齐
包含8字节类型时，整体对齐提升到8。
```cpp
struct C {
    char a;     // 0
    double b;   // 有效对齐8，偏移1→填充7，偏移8开始，占8字节（8-15）
    int c;      // 有效对齐4，偏移16刚好，占4字节（16-19）
};
// 整体有效对齐 = max(1,8,4) = 8
// 总长度20 → 末尾填充4字节到24
// 最终 sizeof(C) = 24
```

### 三、控制对齐的常用方式
#### 1. `#pragma pack(n)` （编译器通用）
临时修改指定对齐值，n可取1、2、4、8、16。
```cpp
#pragma pack(1) // 指定1字节对齐（无填充）
struct Pack1 {
    char a;
    int b;
    short c;
};
#pragma pack() // 恢复默认对齐
// sizeof(Pack1) = 1+4+2 = 7
```

#### 2. 编译器特定属性
- GCC/Clang：`__attribute__((packed))` 取消对齐，紧凑排列
  ```cpp
  struct Packed {
      char a;
      int b;
  } __attribute__((packed)); // 大小=5
  ```
- MSVC：`__declspec(align(n))` 指定结构体整体对齐
  ```cpp
  __declspec(align(16)) struct Align16 {
      int a;
  }; // 整体对齐16，大小=16
  ```

#### 3. C++11 标准关键字 `alignas` / `alignof`
- `alignas(n)`：指定变量或类型的对齐值，替代编译器特定属性
  ```cpp
  struct alignas(16) MyStruct {
      int a;
      char b;
  }; // 整体对齐16，大小=16
  ```
- `alignof(类型)`：获取类型的有效对齐值
  ```cpp
  std::cout << alignof(int); // 输出4
  ```

### 四、为什么需要内存对齐
1. **访问效率**：CPU以「字长」（64位为8字节）为单位访问内存。非对齐数据会跨多个访问块，需要多次读取+数据拼接，性能显著下降。
2. **硬件兼容性**：ARM等RISC架构不支持非对齐内存访问，直接触发硬件异常导致程序崩溃。

### 五、常见注意点
1. **空结构体大小**：C++中空结构体/空类的`sizeof`为1字节——保证每个实例拥有唯一内存地址。
2. **位域对齐无标准**：位域的打包规则由编译器自行实现，同类型位域通常会合并到同一存储单元，跨类型行为不统一。
3. **32/64位差异**：主要体现在指针长度（32位=4，64位=8），其余基本类型对齐规则一致。


### 统一示例
```cpp
struct S { char a; int b; double c; };
```
环境：64位、默认8字节对齐；`char=1`、`int=4`、`double=8`

---

### 1. 默认状态（基准）
- 成员偏移：`a=0`，`b=4`（中间补3字节），`c=8`
- 总大小：16 字节，整体对齐=8
- 内部按各类型自然对齐

### 2. `#pragma pack(2)`（压缩对齐）
```cpp
#pragma pack(2)
struct S { char a; int b; double c; };
#pragma pack()
```
- 成员偏移：`a=0`，`b=2`（中间只补1字节），`c=6`
- 总大小：14 字节，整体对齐=2
- **核心**：从内部每个成员的对齐规则就开始缩小，成员相对位置改变，整体体积压缩。

### 3. `alignas(32)`（放大对齐）
```cpp
struct alignas(32) S { char a; int b; double c; };
```
- 成员偏移：`a=0`，`b=4`，`c=8`（和默认排布**完全一致**）
- 总大小：32 字节，整体对齐=32（末尾额外补16字节）
- **核心**：内部排布丝毫不改，只放大结构体最终的整体对齐边界，仅增加末尾填充。

---

### 一句话总结
`pack` 改内部成员的对齐规则，从根上压缩体积；`alignas` 不动内部，只在结尾放大整体对齐边界。


pack不光影响内部对齐，同样影响最终的整体对齐

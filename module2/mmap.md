# mmap 核心知识点总结

## 一、传统 `read()` 与 mmap 读取流程对比

### 1. 传统 `read()` 读取流程

- 两次数据拷贝：
  1. 磁盘 → 内核页缓存（DMA 拷贝，无 CPU 参与）
  2. 内核页缓存 → 用户空间缓冲区（CPU 拷贝）
- 两批独立物理页框：内核页缓存占一批，用户缓冲区占另一批，内核和进程通过各自虚拟地址访问不同物理页。
- 额外开销：每次读取都触发系统调用，产生上下文切换开销。

### 2. mmap 读取流程

- 仅一次磁盘到内存的 DMA 拷贝（数据加载到内核页缓存），省去内核页缓存到用户空间的 CPU 拷贝。
- 仅一批物理页框：进程的用户虚拟地址直接映射到内核页缓存的物理页，内核和进程通过各自虚拟地址访问同一份物理内存。
- 加载时机：调用 mmap 时仅建立地址映射，不加载数据；首次访问对应地址时触发缺页中断，才以页为单位加载数据。

## 二、mmap 核心本质（三层能力叠加）

1. 地址映射层：在进程虚拟地址空间与磁盘文件之间建立字节一一对应的映射关系，将文件 IO 操作转化为普通内存读写指令，省去 `lseek`、`readwrite` 等系统调用的上下文切换开销。
2. 按需加载层：数据不会全量载入物理内存，仅当进程访问到对应虚拟地址时，才以页（默认 4KB）为单位从磁盘加载；未访问的数据始终留在磁盘，不占用物理内存；内存不足时内核自动淘汰冷页。
3. 共享物理页层：加载的数据位于内核统一管理的页缓存中，用户虚拟地址直接映射到这批物理页，实现零拷贝访问，这是 mmap 高性能的核心来源之一。

### 对比场景

磁盘上有二进制文件 `data.bin`，内部连续存储 10000 个 4 字节的 int 型整数。我们需要**随机读取第 1234、5678、9999 个整数**并计算三者之和。

---

### 一、传统 IO（lseek + read）实现

```
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main() {
    int fd = open("data.bin", O_RDONLY); // 系统调用1：打开文件
    int val1, val2, val3;

    // 读第1234个int
    lseek(fd, 1234 * 4, SEEK_SET);      // 系统调用2：移动文件指针到指定偏移
    read(fd, &val1, sizeof(int));       // 系统调用3：读取4字节到用户空间

    // 读第5678个int
    lseek(fd, 5678 * 4, SEEK_SET);      // 系统调用4：再次移动指针
    read(fd, &val2, sizeof(int));       // 系统调用5：再次读取

    // 读第9999个int
    lseek(fd, 9999 * 4, SEEK_SET);      // 系统调用6：第三次移动指针
    read(fd, &val3, sizeof(int));       // 系统调用7：第三次读取

    int sum = val1 + val2 + val3;
    printf("sum = %d\n", sum);

    close(fd);                          // 系统调用8：关闭文件
    return 0;
}
```

#### 传统 IO 的开销点

1. **系统调用次数随读写次数线性增长**：每读1个位置，必须调用 `lseek` + `read` 2次系统调用；3次读取共触发6次读写相关系统调用，加上`open/close`总共8次。
2. **每次系统调用都有上下文切换**：用户态→内核态→用户态，两次模式切换。
3. **必须数据拷贝**：数据从内核页缓存拷贝一份到用户空间变量，共3次拷贝。
4. **代码繁琐**：需要手动计算字节偏移、管理文件指针、处理读写长度。

### 二、mmap 实现

```
#include <fcntl.h>
#include <unistd.h>
#include <sys/mman.h>
#include <stdio.h>

int main() {
    int fd = open("data.bin", O_RDONLY);       // 系统调用1：打开文件

    // 系统调用2：一次性建立整个文件的地址映射
    // 返回映射区首指针，后续直接通过指针访问文件
    int *ptr = mmap(NULL, 10000 * 4, PROT_READ, MAP_PRIVATE, fd, 0);

    // 👇 以下读写没有任何系统调用，就是普通内存数组访问
    int val1 = ptr[1234];  // 等价于 lseek + read
    int val2 = ptr[5678];  // 等价于 lseek + read
    int val3 = ptr[9999];  // 等价于 lseek + read

    int sum = val1 + val2 + val3;
    printf("sum = %d\n", sum);

    munmap(ptr, 10000 * 4); // 系统调用3：解除映射
    close(fd);               // 系统调用4：关闭文件
    return 0;
}
```

#### mmap 的核心优势（对应地址映射层）

1. **读写阶段零系统调用**：映射建立后，`ptr[下标]` 就是普通内存访问，完全替代了 `lseek`（下标偏移对应文件偏移）和 `read`（解引用直接取值），无论读多少个位置，读写相关的系统调用次数都是0。
2. **零数据拷贝**：用户虚拟地址直接映射内核页缓存的物理页，CPU直接读取物理内存，不需要内核→用户空间的拷贝。
3. **代码极简**：直接把文件当内存数组用，不用管理文件指针、不用计算字节偏移、不用处理读写长度，和操作普通内存完全一致。

### 三、直观对比总结

| 维度 | 传统IO（3次随机读） | mmap（3次随机读） |
| --- | --- | --- |
| 读写相关系统调用数 | 6 次 | 0 次 |
| 上下文切换次数 | 12 次（每次调用2次） | 0 次 |
| 数据拷贝次数 | 3 次 | 0 次 |
| 代码复杂度 | 需手动管理偏移和IO | 直接数组访问 |

补充说明：mmap第一次访问某一页时会触发**缺页中断**（按需加载层），本例子中3个位置分属3个不同的4KB页，共触发3次缺页中断。但缺页中断按页触发，一次加载可支撑页内所有后续访问；而传统IO每读一个位置都要完整走一次系统调用流程，读写次数越多，mmap优势越明显。

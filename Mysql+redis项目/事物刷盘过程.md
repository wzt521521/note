1.准备阶段

给事物分配事物ID，生成undo log（还没有写入）

2.执行阶段

先查询对应数据是否在内存，如果没有就调入内存缓冲池buffer pool

然后加入排他锁，实现隔离，然后写入undo，方便其他事物进行读取历史版本

然后开始更新buffer pool的内存数据，此时这页内存为标记为脏，然后生成redo log

状态总结：全部在内存进行操作，包括undo log ,buffer pool , redo log
此时如果数据库宕机，全部消失，事物被视为未执行

3.commit事物提交

先把redo写入磁盘，然后释放排他锁，其他事务可以读取最新的内存数据

标记事务已经提交

4.异步刷盘

数据库会在后台异步刷脏页（和 commit 不同步，后台线程执行）。

后台 Page Cleaner 线程，在空闲 / Buffer Pool 不够的时候，**异步**把 Buffer Pool 里的脏页写入磁盘 `ibd` 表文件。

- 这一步可能在 commit 后几毫秒、几秒甚至几分钟之后才发生
- 不是事务流程的一部分，属于后台回收任务
- 刷完之后：内存页和磁盘 ibd 文件一致，脏页变干净页


## 如果中途执行 ROLLBACK（替代 commit 的分支）

```
START TRANSACTION;
UPDATE users SET gold = gold -100 WHERE id=1001;
ROLLBACK;
```

1. **不操作 redo 持久化，不写 commit 标记**
2. 读取 undo log 里保存的旧版本数据
3. 在 Buffer Pool 内存中，把脏页**恢复回原始值**，脏页变回干净页
4. 释放行锁，事务结束

> 
> rollback**不会删除 redo log**；redo 日志依旧存在，只是事务没有 commit 标记，崩溃恢复会直接忽略这条事务。
> rollback 只依靠 undo log 回滚内存中的数据。

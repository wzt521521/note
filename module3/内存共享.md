### 3.5 Shared Memory 小结

这部分的核心是：**通过 `mmap()` 创建一块可以被多个进程共同映射的内存区域。**

我们使用的系统调用是：

```cpp
void* mmap(
    void* addr,
    size_t length,
    int prot,
    int flags,
    int fd,
    off_t offset
);
```

各参数含义：

- `addr`：希望映射到哪个虚拟地址；传 `nullptr` 表示让内核自动选择。
- `length`：映射多大，例如 `sizeof(int)`。
- `prot`：访问权限。`PROT_READ` 可读，`PROT_WRITE` 可写。
- `flags`：映射类型。`MAP_SHARED` 表示修改对其他共享该映射的进程可见；`MAP_PRIVATE` 表示私有映射，写入时触发 COW。
- `fd`：要映射的文件描述符；使用 `MAP_ANONYMOUS` 时通常传 `-1`。
- `offset`：从文件哪个偏移开始映射；匿名映射通常传 `0`。

我们实际使用的是：

```cpp
mmap(
    nullptr,
    sizeof(int),
    PROT_READ | PROT_WRITE,
    MAP_SHARED | MAP_ANONYMOUS,
    -1,
    0
);
```

其中最关键的是：

```cpp
MAP_SHARED
```

此时：

```text
Parent ─┐
        ├── shared memory
Child  ─┘
```

子进程执行：

```cpp
*value += 100;
```

父进程之后可以看到这个修改，所以：

```text
Child 看到 200
Parent 也看到 200
```

而换成：

```cpp
MAP_PRIVATE
```

则写入时发生 Copy-on-Write：

```text
Parent page: 100
Child page:  200
```

父进程看不到子进程的修改。

最后释放映射使用：

```cpp
int munmap(void* addr, size_t length);
```

参数分别是映射起始地址和映射长度。

这一节最重要的一句话是：

> `MAP_SHARED` 解决“多个进程能不能访问同一份数据”，但不解决“多个执行流同时访问时是否安全”。

因此，共享内存只是为后面的 race、mutex、atomic 铺路。
